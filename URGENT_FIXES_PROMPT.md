## ❌ ПРОБЛЕМА 1: ВИДЕО MAL0 - СЕРАЯ ОБЛАСТЬ СНИЗУ

**Описание:** 
В окне MAL0 видео отображается корректно по размеру, но снизу остается серая/черная пустая область, которую нужно заполнить видео.

**Текущее состояние:**
- Файл: `/app/frontend/src/components/VideoBackground.css`
- object-fit: contain (показывает видео полностью, но оставляет пустоту)
- Контейнер: height: 400px

**Что НУЖНО:**
Заполнить серую область снизу видео, сохранив при этом правильный размер самого видео (не растягивать).

**Возможные решения:**
1. Уменьшить высоту контейнера `.video-background-container` под пропорции видео
2. Использовать object-fit: cover с object-position для центрирования важной части видео
3. Установить фиксированные пропорции видео через aspect-ratio
4. Добавить медиа-запросы для разных размеров экрана

**НЕ ДЕЛАТЬ:**
- НЕ использовать object-fit: cover без настройки object-position (это растягивает видео)
- НЕ менять размер самого видео, только контейнер

## ❌ ПРОБЛЕМА 3: СИСТЕМА ДОСТУПА НЕ РАБОТАЕТ НА FRONTEND

**Описание:**
Пользователь создал новый аккаунт и видит ВСЕ досье объектов, хотя должен видеть только те, к которым у него есть доступ согласно уровню допуска.

**Критичность:** 🔴 ВЫСОКАЯ - это проблема безопасности!

**Где искать проблему:**

### 1. Проверить DossierList.js или HomePage.js
Файл: `/app/frontend/src/components/DossierList.js` или `/app/frontend/src/pages/HomePage.js`

**Что проверить:**
- Отправляется ли токен авторизации в запросе к `/api/scp`
- Используется ли правильный header: `Authorization: Bearer {token}`
- Правильно ли обрабатывается ответ от backend

**Пример правильного запроса:**
```javascript
const token = localStorage.getItem('token'); // или из context
const response = await fetch(`${BACKEND_URL}/api/scp`, {
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  }
});
```

### 2. Проверить backend endpoint GET /api/scp
Файл: `/app/backend/server.py` (строки 239-263)

**Что проверить:**
- Функция правильно получает `current_user` через `Depends(get_current_user)`
- Если пользователь не авторизован (`current_user` is None), используется clearance_level = 1
- Фильтрация объектов по `required_clearance <= clearance_level` работает корректно

**Текущая логика (должна быть):**
```python
clearance_level = current_user["clearance_level"] if current_user else 1
```

### 3. Проверить AuthContext или токен в localStorage
Файл: `/app/frontend/src/App.js` или context файл

**Что проверить:**
- Токен сохраняется после login: `localStorage.setItem('token', access_token)`
- Токен используется во всех API запросах
- Пользователь правильно устанавливается в state/context

### 4. Проверить систему регистрации
Файл: `/app/backend/server.py` (строки 136-184)

**Что проверить:**
- Новые пользователи получают clearance_level = 1 по умолчанию
- Невозможно зарегистрироваться с clearance_level >= 5

**Текущая логика (должна быть):**
```python
clearance_level = min(user_data.clearance_level, 4)
```
